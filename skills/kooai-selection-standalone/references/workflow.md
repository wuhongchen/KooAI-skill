# 数据查询与选品工作流

## 1. 卖家诊断

将输入整理成七项画像：卖家类型、目标、优势、弱项、库存策略、适合机会、避免机会。排序规则必须引用这份画像，不能只把非空对象当作“已适配”。

## 2. MCP 数据采集

按任务范围调用已配置的 `kooai-market-data` MCP。Skill 自主选择 MCP 工具和分页深度，达到回答所需证据后停止：

1. 类目和周度全盘数据：确定需求面、价格带、类目覆盖和数据日期。
2. 商品数据：保留商品 ID、销量、PV、价格、排名、评论与配送标识。
3. 关键词或趋势数据：判断持续需求、短期变化和季节性。
4. 每次结果记录工具名、`data_date`、warnings；结果日期冲突时以可验证的最晚完整 T-1 快照为准，并标注差异。

不得直连 cpdata 数据库，也不得把静态记忆当成本次 MCP 事实。

类目与商品数据是正式候选的主要基础；榜单只能用于候选发现或旁证。复合关键词返回 0 时，改用类目、价格和数值条件查询，不得把零结果解释为无需求，也不得直接切换为榜单选品。

## 3. 机会构造

从以下交集产生候选，而不是直接复制销量榜：

- 有需求证据，但卖家集中度、评价壁垒或品牌壁垒相对可进入。
- 能用规格、数量组合、材质、使用场景或内容表达形成差异。
- 符合卖家库存、履约、认证和退货承受能力。
- 趋势与季节法只改变时机判断，不替代竞争与单位经济证据。

## 4. 七关漏斗

依次评估卖家适配、需求、趋势与时机、竞争、差异化、单位经济、合规与履约。每关写明：结论、证据、原因、缺失数据、置信度、事实或推断。任一关键关卡未知时，总体不得包装为正向通过。

## 5. 排序与报告

优先顺序：新卖家可进入性 → 可验证需求 → 差异化空间 → 履约/退货/合规风险 → 单位经济 → 放量潜力。输出入选理由和第一轮验证动作；成熟头部商品可作为需求证据，但不能自动成为推荐候选。

根据证据覆盖度选择分析模式：

- `full_data`：类目、商品和关键验证证据完整，可给“优先验证”（`validate`）。
- `partial_evidence`：核心需求成立，但竞争、趋势、评论或合规证据缺失，只能“小批验证”（`small_batch`）或“观察”（`observe`）。
- `exploratory`：主要依赖榜单、单商品或其他线索，只能“观察候选”（`observe`），不得写成正式推荐。

每次报告记录 `mcp_tools_used`、`data_snapshots`、`screening_funnel`、`ranking_usage` 和 `limitations`。`ranking_usage` 只能是 `not_used`、`candidate_discovery`、`supporting_signal` 或 `primary_signal`；若为 `primary_signal`，报告必须是 `exploratory`。

将报告写入临时 JSON（不得包含 Key），启动本地适配器，提交并打开独立页面。导出内容必须与报告快照一致。

MCP 鉴权、初始化或真实查询失败时停止。类目或商品核心数据为空时，可以生成解释查询范围与缺口的 `exploratory` 空报告，但不得生成正向候选。趋势、评论等辅助证据失败时可降级为 `partial_evidence`，披露限制并保持相应关卡 `UNKNOWN`。

## 6. 本地页面

将不含密钥的不可变报告快照提交到本地页面。页面可在当前候选集合内按关键词、类目、市场指标、评论、配送、七关结论与推荐状态筛选和排序；CSV/XLSX 只能导出当前可见的候选行。
