# KooAI 场景日用与消耗品选品

从「人群 → 场景 → 日常任务 → 用品/耗材 → 韩国类目 → 动销 → 进入空间」寻找机会。日常使用不等于高频购买；消耗品也不天然低竞争。此 Skill 是 Agent 工作流，不是已部署的采集服务。

## 本轮范围

从当前请求和已确认上下文整理：场景、卖家阶段、排除项、时间窗口、数据入口、是否找货算价、数量或查询预算、交付形式。已有答案不重复问；只询问会实质改变任务的缺项。

- 市场默认韩国 Coupang，截止日默认 T-1；使用可用项目日期工具，不把最后一次入库日期伪装成 T-1。
- 未指定场景：先覆盖厨房、卫浴、清洁洗衣、收纳、办公、宠物日常护理，说明这只是本轮探索范围，不是全站扫描。
- 有当前卖家条件就沿用；无上下文时用「新卖家小批验证」作为明确假设。没有固定进货价、净利润、日单量或候选数门槛。
- 用户要求低合规负担/排除 KC 时，分别列需要 KC、确认不适用 KC、待核验；后两者不能混同。食品接触、卫生用品、化妆品等其他监管另查。未知者留在待核验表，不挤掉已经查到的市场事实。
- 食品、儿童、电器、电池、季节性、大件等排除项按本轮配置，不能把本次厨房案例固化为所有用户的永久条件。

## 执行

执行市场分析前读 [references/method.md](references/method.md)。

1. **场景拆解**：为每个场景列日常任务、目标人群、现用方案及用品。区分耐用品、磨损替换品、一次性消耗品、补充装。填写韩文搜索词和可能的类目，词表只是入口，不是市场证据。
2. **身份清洗**：从类目树定位实际范围，检查商品标题/规格。排除同词异物和用途污染；如一次性丁腈手套不等于隔热手套，食品用不等于医疗用。场景可跨多个类目，全局按产品 ID 去重。
3. **查市场**：用已认证 KooAI MCP，或用户指定且可用的只读 RDS；先确认真实查询成功和实际字段。服务不可用就交付研究框架/已完成部分，不生成市场数字。有 `category-data-explorer` 时用于类目统计；没有时按本 Skill 的数据契约执行。
4. **查动销和空间**：同时看覆盖率、动销率、销量/PV、Top1/5/10 份额、评价壁垒、配送分布、价格带。头部款证明需求；重点另找有 PV、有销量、评论相对少的中腰部款。类目阈值按本轮分布解释，不拿低评价或首次发现日期直接证明新品机会。
5. **查复购逻辑**：记录消耗机制、替换原因、每次用量、包装数量、存储体积和季节性。没有订单复购或可靠使用证据时，复购周期是待验证假设，不报实际复购率。大包装低客单要检查单件/每100只/每米等单位价格和体积运费。
6. **查买家痛点**：有评论正文时按产品和日期去重，区分尺寸、耐用度、破损、异味、包装、使用便利等；记录正文样本量与覆盖。没有正文时列缺失，不编造痛点或“无差评”。
7. **货源与利润**：用户要求完整选品、找货或利润时，对优先方向挑代表商品，调用实际可用的 `1688-product-find` 或用户指定的 Ego 路径。遵守 method.md 的同规格与统一算价要求；只问类目方向时不自动扩大为批量采购核价。
8. **判断**：需求、竞争、货源、利润、风险五列写中文短结论与依据；原七关可留证据明细，但不堆在主表。只有市场证据时为「值得验证」；货源/成本/合规满足且样品待检时为「优先拿样」；不足为「观察/待核验」；命中硬排除为「排除」。不承诺能卖或盈利。

## 交付

普通问答给场景/类目对比表和候选表。用户要求完整报告时，生成可筛选的本地 HTML 与 XLSX；仅指定一种形式则只做该形式。创建 XLSX 时使用可用的电子表格 Skill。

- **场景总览**：场景、任务、用品/耗材类型、中韩关键词、类目、消费/替换机制、N/V/M/Z/U、三项动销比例、覆盖销量/PV、头部集中度、火箭占比、结论及依据。
- **商品明细**：中文/韩文名、图片、类目、产品 ID、规格、售价及币种、销量/PV、评分/评论数、配送、指标日期、入围/排除原因、Coupang 链接。
- **货源算价**（执行时）：对应产品 ID、1688 图片/标题/规格/链接、MOQ、报价和单位、成本证据级别、换算后的采购成本、运费/税费/广告/退货、利润金额/利润率/ROI、保本价/目标价、配置与算价日期。
- **排除与待核验**：保留不合格、未知、过期和未匹配商品及原因；不得只导出成功行。
- **数据说明**：实际范围、日期、覆盖、阈值、默认参数、事实/推断、合规证据及未执行环节。

表格以名称、图片、价格、销量和链接在前，ID/审计字段靠后；长证据和算价公式点击展开。图片完整显示并可查看大图；金额/百分比统一保留两位小数，保留币种和计算口径。HTML 筛选后的可见行支持 CSV 导出，导出与页面行数一致。所有生成文件放独立输出目录，不修改业务前端。

## 调用示例

> 使用 $kooai-scenario-selection，分析韩国厨房和卫浴的日常消耗品。排除儿童、电器、大件、季节性及需要 KC 的产品，合规不明单列。找有动销且评价壁垒相对低的方向，核验代表商品的1688货源并用统一模型算价，输出含图片的 Excel 和本地页面。

只读分析不自动写飞书、下单、联系供应商、发布、推送 GitHub或创建定时任务。用户另行要求这些动作时按对应授权执行。
